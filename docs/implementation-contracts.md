# 工程接口与数据约定

版本：0.1.0，2026年10月19日。

## 写入与身份

浏览器使用HttpOnly、SameSite Strict会话Cookie。写入需要当前会话CSRF令牌，服务端校验Origin。个人与科研角色在Go路由上隔离，浏览器隐藏菜单不能代替权限校验。数据库不直接暴露宿主端口。

模型只提议有类型的动作。用户看见对象、字段和版本并确认后，Go在事务内重验归属、版本、有效期与字段类型。确认回执持久保存，重试不重复创建记录。删除的回执独立于被删聊天，重复确认仍可安全返回。

内部服务使用Bearer认证，读取健康上下文及图片还需绑定单个run、两分钟有效的签名凭据；签名密钥只传给Go。工具路径不接受用户ID、SQL或任意外部URL。

## 主要API

| 前缀 | 角色 | 操作 |
| --- | --- | --- |
| `/v1/auth` | 登录流程 | register、login、me、logout；注册不能指定科研角色 |
| `/v1/health/state` | user | 档案、事件、观察、用药、核对、提醒、用途与待确认动作 |
| `/v1/health/daily-summary` | user | 首次、当前不适、已结束有历史三种首页与真实记录摘要 |
| `/v1/health/conversation` | user | 最近消息与运行状态 |
| `/v1/health/conversations/:id/messages` | user | 图文消息，client_id幂等，返回202与run_id |
| `/v1/health/runs/:id` | user | 状态、持久SSE事件与取消 |
| `/v1/health/runs/:id/retry` | user | 失败/取消的原消息用新运行重试，原附件保留、幂等 |
| `/v1/health/products` | user | 当前可发布产品身份及来源，不返回用量原文 |
| `/v1/health/actions/:id/confirm`、`reject` | user | 确认业务写入或不保存 |
| `/v1/health/attachments` | user | 受控上传与按归属读取 |
| `/v1/health/signals` | user | 有时间窗、否定和来源的历史知识匹配 |
| `/v1/health/export` | user | 结构化记录、消息及附件编号清单，不包含登录凭据 |
| `/v1/research/overview`、`records` | researcher | 使用同一队列条件的汇总、明细和来源 |
| `/v1/research/cohorts` | researcher | 保存和应用队列定义 |
| `/v1/research/snapshots` | researcher | 冻结输入、哈希和成员授权版本 |
| `/v1/research/snapshots/:id/package`、`bundle` | researcher | 输入JSON、合成数据可执行任务包 |
| `/v1/research/runs` | researcher | 本地参考或SciencePal任务、详情、结果导入和控制 |
| `/v1/research/export`、`knowledge` | researcher | 受控JSON/CSV导出、护理参考与科研文献 |

SSE事件有持久递增编号，支持Last-Event-ID补拉。模型的原始JSON片段不直接显示为医疗建议，只在验证后发出正文增量。模型失败保留消息，不自动启用测试Provider。

动作包括创建不适、每日观察、记录与更正用药、归档、档案更新、独立研究/影像授权、提醒创建/更新和健康记录删除。同日观察更新版本与修订表，更正用药使用原记录ID并保存旧版本。

## 时间和未知

记录时间为UTC，个人IANA时区默认Asia/Shanghai。观察发生日与补记时间分开。症状起病是否明确另存onset_known；未提供时只用建档日期作观察锚点，不把建档时间当作已知起病。真实研究的初始覆盖按建档结构化字段统计，不把同日后补信息冒充首次已知。缺失评分不补0；明确未用、记不清和没有记录分别统计。每日提醒按个人时区推进日历日；站内到期待办持久保存，浏览器关闭不影响调度。

## 科研分母与隐私

默认展示固定合成数据，未经用户授权不自动纳入个人记录。真实结构化研究需要至少5名当前授权参与者；这个展示阈值不等于匿名化保证。

真实数据的参与者、事件和患者日分别统计，同一参与者相同实际日期的患者日去重；各段事件相对日的逐日表另有明确口径。字段覆盖和评分配对按事件统计。多个事件的患者日用药状态若有明确使用则归为使用，其次为未知；不能把某段事件的“未用”推为当天所有事件均未用。

真实研究不开放聊天、备注、产品原始名称与图片；产品字段使用受控成分词表，不能归一的成分保留信息缺口。研究编号和患者日键用服务端HMAC生成，研究端看不到身份映射。合成样例可以查看逐条示例原文，不能因此开放真实原文。

研究快照固定输入和授权版本；运行、导出、下载与结果查看重新检查授权。撤回使旧快照失效并阻止旧结果再访问。候选不等于已经证实滥用，自评分变化不代表痊愈，合成数据不能估计真实人群频率。

## 存储边界

PostgreSQL保留事实、授权、任务、审计、快照和检查点。pgvector已安装并提供向量字段；当前小型知识包用确定性查询，没有伪造已完成的向量嵌入或召回评估。Redis只缓存公共知识和限流，丢失后回源，不缓存用户聊天、图片或授权决定。

私有文件经过内容校验、像素上限、方向修正与重新编码，移除EXIF。当前使用权限隔离的本地Docker卷，并未声称已实现应用层文件加密。生产部署使用HTTPS及部署方控制的加密磁盘/备份。

## 产品说明、冻结输入与比较

产品说明按(id, version)不可变发布，来源审阅与撤回走管理员CLI，模型不能调用发布功能。关联用药需匹配名称、地区、规格、剂型与途径；`state.product_information`单独控制用量原文门槛。只有明确符合年龄/地区、孕哺以及已知过敏、病史、无额外用药等条件时才可显示匹配原文。说明过期或撤回后停止发布，实际用药事实保留。详见`product-knowledge.md`。

队列统一使用source、topic、category、window_days及可选start_from、start_to、product_id、availability；非法范围返回400，前端隐藏旧结果并禁止导出。纳入与顺序排除计数可核对。真实研究使用只读REPEATABLE READ事务，快照清单保存实际截点、队列、输入/脚本哈希、方法/知识/规则/数据版本及随机种子。ZIP与SciencePal上传包含同一manifest.json。

任务重跑复用冻结快照并创建新任务，不覆盖原结果。比较在服务端重新检查访问权限后读取两项已完成结果，显示共同指标差值、版本与输入哈希；不同输入需结合队列解释。

模型调用另存实际Provider、模型名称、接口主机名、温度、提示模板与上下文哈希、测试模式标记。这些值由运行时记录，不接受模型自报；不保存API Key。


每个已执行节点以单调时钟记录毫秒耗时及完成/等待确认/失败状态，运行尝试汇总和供应商用量进入持久run_events。`GET /v1/health/runs/:id`仅向所有者返回telemetry；成功回复元数据保留runtime_metrics。worker尝试次数、重试关联与失败原因来自数据库。供应商流中usage的空choices结束帧可正常处理，仅接受非负整数Token计数；未提供的字段为null。没有价格依据时成本amount/currency为null，不以Token数或测试输出推算账单。设置MODEL_STREAM_USAGE=false可兼容不支持stream_options的服务，届时用量仍可能未知。
