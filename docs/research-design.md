# 科研端研究设计与实现说明

更新：2026年10月18日。产品名为伴AI·健康伙伴；用户端与科研端独立。所有当前统计来自固定合成样例，未开展真实受试者研究。

## 科学定位

本项目最适合验证的是：**连续对话记录能否更完整地还原院外轻症过程，并为自主用药和历史症状组合保留可核实的情境？**

首阶段关注患者自报信息的采集质量、时间关系、缺失与可追溯性。早期疾病线索是待核实的信息组合；没有确诊结局和外部验证时，不报告患病概率、早诊率或临床筛查性能。

## 研究热点如何转化为项目问题

以下是对原始研究和官方资料的项目设计推论，不是原论文对本产品的背书。

| 依据 | 与项目相关的问题 | 已落实的设计 |
| --- | --- | --- |
| [Nature Health，2026：症状报告与人机交互](https://www.nature.com/articles/s44360-026-00116-y) | 用户面对AI时，报告方式及质量可能不同。模型能力不能替代信息采集质量的评估。 | 首次描述与连续记录的同字段对照；按原文与字段溯源。 |
| [FDA，2025：适合用途的临床结局评估](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/patient-focused-drug-development-selecting-developing-or-modifying-fit-purpose-clinical-outcome) | 患者自报数据需要清楚的概念、用途和测量依据。 | 定义共同字段、回忆时间与分母；自评分不冒充已验证的临床结局量表。 |
| [Nature，2026：多次对话与疾病管理](https://www.nature.com/articles/s41586-026-10764-5) | 长程上下文、历史建议和时序一致性成为医疗对话AI的研究方向。 | 跨日证据、分析截点、否定、未知和未来信息隔离。 |
| [Nature Medicine，2026：多模态诊断对话](https://www.nature.com/articles/s41591-026-04371-0) | 图像应放在对话情境中评估，而非孤立处理。 | 图片保留质量、来源与独立研究授权；当前只展示元数据，没有运行图像模型。 |
| [WHO，2026：抗微生物药物耐药](https://www.who.int/news-room/fact-sheets/detail/antimicrobial-resistance)；[WHO，2025：全球耐药监测](https://www.who.int/publications/i/item/9789240116337/) | 院外用药情境可连接合理用药研究；耐药监测需要其自身的病原与检测数据。 | 抗菌药“使用依据未记录”作为待补信息；没有检测数据，不计算耐药率。 |
| [FDA：真实世界数据与证据](https://www.fda.gov/science-research/science-and-research-special-topics/real-world-evidence) | 收到数据并不自动产生可靠证据。 | 报告研究问题、数据适用性、输入哈希、规则版本和解释范围。 |

这些研究的场景、参与者和评估方法与本产品不同，因此没有把其模型性能或临床结果迁移到项目成绩中。FDA资料用于方法借鉴，不表示本项目满足监管级研究要求。

## 分析工作台

### RQ01 连续记录补充了什么

- 单位：同一参与者的一段轻症事件。
- 对照：首次描述，与开始后3天或7天内的可用记录。
- 共用字段：主要不适、开始与持续、不适自评分、日常活动影响、实际用药状态。
- 指标：5项可解释字段的覆盖数 / 参与者数×5，以及覆盖率差值，单位为百分点。
- 变化描述：首次记录本来无法提供的纵向信息，单独显示，不计入共同字段改善率。
- “可解释”：窗口内至少一次明确提供过该字段。明确未知不被补为已知；这不是字段准确率或逐日完整率。
- 当前数据：人工构造的原文与字段配对，没有运行语言模型，因此不是AI提取效果实测。
- 后续验证：等时长随机或交叉比较，双人盲评，记录负担与误差；按参与者划分数据，避免患者日泄漏。

当前合成数据的高覆盖率是样例构造的结果，只用来检查计算和交互。更长时间自然会带来信息增量，配对差值不能单独归因于AI。

### RQ02 院外用药有哪些信息值得核实

只在“明确使用”的观察日运行规则，同一参与者同一规则只计一次。症状原文与结构化用药自述使用独立来源ID，字段保留来源映射；点击候选定位到对应记录。

| 规则 | 实际检查 | 输出范围 |
| --- | --- | --- |
| 同日重复成分线索 | 不同产品在同日包含相同的已知成分 | 可能重复，仍需具体时间、剂量与使用依据；不是过量结论 |
| 抗菌药依据待补 | 自报抗菌药的使用依据为空 | 需要补充情境，不推断一定为无处方使用 |
| 外用激素信息缺口 | 记录缺少强度或使用部位 | 不按用了几天直接认定滥用 |
| 成分无法归一 | 明确使用的产品没有可核实成分 | 需要包装或完整产品资料 |

成分重复的设计参考[FDA对乙酰氨基酚资料](https://www.fda.gov/drugs/safe-use-over-counter-pain-relievers-and-fever-reducers/acetaminophen)，外用激素适用信息参考[英国NHS机构资料](https://www.guysandstthomas.nhs.uk/health-information/topical-steroids)。这里不输出个体剂量、处方或停续药决定；国外资料还需按产品与地区核实。

产品名与成分包括明确标注的合成占位内容，不是药品推荐目录。抗菌药和外用激素样例是用于研究信息缺口的边界场景，不扩大患者端自主用药范围。

### RQ03 缺失会怎样影响结果

按仍应记录的患者日计算分母；用户标记结束之后，不继续累积应记录日。区分明确使用、明确未使用、用户记不清和没有当天记录。

显示“仅已明确状态中的使用比例”，再展示将未知全部当作未用或全部当作使用得到的极端上下界。其作用是说明对未知状态的敏感性，不是置信区间，也不证明缺失是随机的。不对症状作插值，不将缺失曲线连成改善趋势。

### RQ04 历史组合是否稳健

独立的四类合成样例：组合齐全、明确否定、信息缺失、未来信息。

- 截点固定为2026年10月18日，使用窗口内每个症状最近的明确断言。
- 窗口可选7或28天，均为工程演示参数，不是临床阈值。
- 明确否定不能因出现关键词而变成命中。
- 没记录不等于明确否定。
- 截点后的记录不得进入当前分析。
- 组合齐全仅输出“需进一步核实”，不输出疾病概率。

例子借用[NHS糖尿病症状与诊断资料](https://www.nhs.uk/conditions/type-2-diabetes/symptoms/)中的相关表现。诊断仍需检查，四个固定样例通过不构成敏感度、特异度或早筛效能证据。

## 页面与功能

| 页面 | 可运行的内容 |
| --- | --- |
| 研究总览 | 科学定位、队列指标、四个研究问题、来源和解释边界 |
| 分析工作台 | 字段配对、用药候选证据、缺失敏感性、时序知识边界检查 |
| 研究设计 | 七份对照方案、固定窗口敏感性结果、赛事证据与执行任务包 |
| 队列与质量 | 症状主题、产品样例类型、3/7天窗口；纳入排除、主题构成和质量分母 |
| 记录溯源 | 六类主题的单例原文、结构化状态、评分轨迹和规则来源ID |
| 数据底座 | 事实与用途分层、数据字典、版本、图片研究排除和授权控制 |
| SciencePal运行 | 浏览器实际计算、输入导出、Python参考脚本下载、报告导入与一致性校验 |
| 研究依据 | 原始来源到项目设计的映射、后续验证协议与限制 |

不足5人的队列暂停聚合结果和导出。部分细分计数也隐藏；这只是演示性小单元抑制，不能视为匿名保证。当前下载的复现包全部是合成数据。真实数据的认证、查询限制和审计尚需服务端实现。

## 当前固定数据与已算出的结果

数据版本：`synthetic-light-illness-v2`。共60份合成事件，六类主题。默认48份具研究授权；个人端明确允许研究后，仅令固定合成样例S001入组，变为49份，撤回后回到48份。不传输个人端文字、症状值或照片。

默认7天配置：

| 指标 | 实际计算结果 |
| --- | --- |
| 应记录患者日 | 324；已结束事件不机械累计到第7日 |
| 已记录患者日 | 267 / 324 = 82.4% |
| 首次共同字段覆盖 | 140 / 240 = 58.3% |
| 窗口内共同字段覆盖 | 235 / 240 = 97.9% |
| 覆盖差值 | 39.6个百分点，仅为合成样例过程指标 |
| 明确使用 / 明确未用 / 记不清 / 缺失 | 137 / 103 / 27 / 57患者日 |
| 已明确状态中的使用比例 | 137 / 240 = 57.1% |
| 全窗口极端上下界 | 137 / 324 至221 / 324，即42.3%—68.2% |
| 有用药候选的参与者 | 32 / 48；样例专门构造了边界问题，不能推为人群比例 |

本地浏览器和Python参考计算对同一输入的全部报告指标一致。该结果是软件计算验证，不是临床效能验证。

## 可复现执行与报告导入

从科研端导出 `health-research-input.json`，并下载 `run_analysis.py`，执行：

```bash
python3 run_analysis.py health-research-input.json --out analysis-output
```

项目自带固定输入，可从根目录复现：

```bash
python3 prototype/research/run_analysis.py analysis/demo-input.json --out analysis/demo-output
node analysis/test_research.js
```

输出 `report.json`、`quality.csv`、`medication_candidates.csv` 和 `patient_days.csv`。输入SHA-256按“对象键排序、数组保序、UTF-8紧凑JSON”计算；当前固定schema中的数值均为整数，不声称实现任意JSON数值的通用规范化标准。

在SciencePal中实际运行时，附平台声明与真实运行链接：

```bash
python3 run_analysis.py health-research-input.json \
  --platform SciencePal \
  --run-url 'https://sciencepal.ai/实际项目或会话链接' \
  --out analysis-output
```

该参数只是记录执行来源，不认证执行地点。比赛仍需要可访问的平台项目、日志和原始产物，不能用文件字段代替平台使用证据。

导入校验包括：文件大小与JSON格式、schema和合成来源、数据/代码/规则/知识版本、队列定义、当前输入哈希、平台链接格式以及所有统计值。改变观察窗口、主题、产品类型或授权后，已有报告失效；旧快照的报告不能充当当前结果。

当前浏览器报告标为 `local-browser`；脚本本地报告为 `local-python`。真实SciencePal执行尚未发生，页面已明确区分。
