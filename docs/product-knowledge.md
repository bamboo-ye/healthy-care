# 版本化产品说明接入

此流程管理参考资料的发布，和用户的每次用药记录分开。用户不需要等待平台医生确认；本轮没有实现医生端或医生审核队列。

主部署默认没有已发布的具体药品说明。真实产品的地区、规格、适用范围和内容仍需专业审阅；导入工具验证格式、版本和审阅记录，不能自动证明审阅者的资质或内容的医学正确性。

## 管理命令

```sh
docker compose exec -T api care knowledge-import < /本机/产品说明包.json
docker compose exec -T api care knowledge-retire 产品编号 版本编号
```

输入只从管理员的标准输入读取，不开放用户端或模型可以调用的发布接口。重复导入相同内容幂等；同一编号及版本的内容不能覆盖，变更需新版本。撤回立即停止该版本的展示与引用，历史实际用药记录保留，导入及撤回留审计。

JSON包含 `schema_version: "1"` 和 `products` 数组。每条必须提供：

| 字段 | 含义 |
| --- | --- |
| id、version | 稳定产品编号与不可变说明版本 |
| name、region、strength、form、route | 产品名称、两位地区代码、规格、剂型、途径 |
| ingredients | 来源说明中的成分数组 |
| information、warnings | 可追溯说明摘要与警示 |
| dosage_label | 仅保存已审阅的说明原文信息；不由模型生成 |
| min_age、max_age | 该产品适用成人范围；需根据来源和审阅决定 |
| amount_unit | 可选的量纲核对单位；不自动换算或判断过量 |
| review_after_days | 可选、该产品特定的复核节点；不套统一停药天数 |
| source_url | 可访问的HTTPS原始来源 |
| review_status | reference或reviewed；撤回用独立命令 |
| reviewer、reviewed_at、review_reference | 发布为reviewed时必填的审阅人、日期和审阅依据 |
| valid_until | 本次内容审阅的有效期，RFC3339 |
| data_origin | reference为真实来源资料；synthetic仅供隔离测试 |

reference条目不会发布用量信息。reviewed必须有审阅依据，且尚在有效期内；填字段本身不能代替真正的专业审阅。过期及撤回版本不会继续发布。

## 用户侧核对

实际用药可以在没有匹配说明时单独记录，不猜测成分。关联具体说明时，产品名称、地区、规格、剂型和途径都要对应，用户核对后保存。

“我的用药”提供可展开的匹配说明、来源、版本、警示和缺失背景。原始用量信息还要求年龄与地区匹配、孕哺情况明确，以及过敏、病史和在用药等背景已明确且没有需要个体复核的复杂情况（在用药列表可包含当前匹配产品本身，不包含其他产品）。背景不足时继续补充，不显示用量原文；AI不把原文改写成个体处方或续方。

记录中的单位和说明量纲不一致时显示待核对。若两次实际记录的时间跨度跨过来源中的复核节点，会列出日期和来源；跨度不证明每天连续使用，不自动给出停药决定。

## 合成测试边界

`tests/product_acceptance.py`使用“合成产品”和example.test验收域名，不对应真实药物或说明。只有显式测试配置允许导入合成条目，主部署默认拒绝。测试内容不构成专业审阅、真实剂量信息或医学能力证据。
