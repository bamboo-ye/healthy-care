# 部署与数据运维

## 本地与公网

本地采用 `compose.yaml`，唯一宿主端口默认绑定127.0.0.1:8780。数据库、缓存与Agent均无宿主端口。镜像基础版本按摘要固定，Go/Python业务与备份进程以UID 10001运行，设置资源上限和10MB×3份日志轮转。

公网部署前配置自己的域名DNS和服务端 `.env`：

```dotenv
APP_ORIGIN=https://你的域名
APP_DOMAIN=你的域名
TLS_EMAIL=证书联系邮箱
COOKIE_SECURE=true
```

```sh
docker compose -f compose.yaml -f compose.production.yaml up -d --build
```

此覆盖文件启用Caddy自动HTTPS及80/443端口。已有演示采用独立隧道方案；部署到自有固定域名时使用上述覆盖。主机防火墙、磁盘加密、密钥管理、监控与备份落点由部署者配置。不要使用本地HTTP配置处理公网真实数据。

## 配置与更新

`python3 scripts/bootstrap.py`只生成缺失配置，不覆写已有密码。数据库密码由首次初始化保存；修改 `.env` 不会自动修改已有数据库角色密码。轮换需在停写与备份后由运维同步修改角色和配置。`RUN_SIGNING_KEY`仅传给Go，Agent收到绑定单个run、两分钟有效的工具访问凭据，不能把它当作通用业务访问令牌。

发布前备份。迁移由一次性migrate服务在事务内执行并留版本，API等待迁移成功；禁止在生产库随意执行测试重置脚本。回滚应用镜像不自动回滚已经写入的数据。

## 备份与恢复

`backup.py`保存PostgreSQL custom-format dump、附件tar与SHA256清单。它暂停服务可用性以取得一致的数据库与附件集；不要把具名卷或restart当作备份。Docker内置backup服务在启动时及每天18:00 UTC（北京时间次日02:00）自动生成一份完整备份。备份进程持有数据库咨询锁，文件删除取共享锁；上传文件不可变，新增对象不会覆盖旧对象，因此冻结数据库引用的图片在归档完成前不会被删除。

自动备份默认保留7天，可用`BACKUP_KEEP_DAYS`调整，0表示不自动清理。备份保存在本机独立`backups`卷，仍需复制到受控的独立存储；没有安装宿主机调度。可用`docker compose logs --tail 30 backup`查看状态；`docker compose cp backup:/backups/备份目录 .local/备份副本`取回后可由同一restore.py恢复。任务失败不记录成功，容器检查最近一次成功时间。

恢复脚本要求新的 `healthy-care-restore-*` 项目，并在目标已有卷时拒绝执行。恢复数据库ACL与schema所有者、Agent检查点、相同UID的附件。先核验数据与文件，再使用单独端口启动恢复服务；不能让恢复环境和主环境争用端口。Redis不备份，会自动重建公共知识缓存。

备份默认未加密，包含健康数据与检查点，权限目录0700、文件0600。上线前使用组织认可的加密存储和备份密钥管理。配置 `.env` 不包含在数据备份内，需单独受控保存。

## 运行状态

- `/healthz`：进程存活；`/readyz`：数据库可用。
- 登录后 `/v1/system/status`：Agent连通性及配置状态。配置存在不等于真实调用验收成功。
- `docker compose ps`：容器健康；`docker compose logs --tail 100 api worker agent-runtime`：有限运维日志。
- 模型失败：用户消息保留，运行标记失败；没有自动降级成测试Provider。
- Redis失败：事实数据继续读取，知识回源数据库，认证采用进程内保守限流。
- worker崩溃：健康任务到租约期后重领；每个对话有数据库锁，业务确认回执防重。
- SciencePal受理不明：保留未知状态，检查平台任务后人工核实；不盲目重试启动。

## 数据清除

用户在对话中确认删除后清除健康业务记录，撤回研究授权，使涉及快照与产物失效；清理任务取消还在执行的Agent任务并删除旧附件与检查点。清理任务保存本次应删文件ID，不删除请求之后的新上传。

保留账户、登录及最小审计记录。审计不复制完整聊天和图片。备份按部署的保留期处理；导出已下载的外部副本不在自动撤回能力范围内。
